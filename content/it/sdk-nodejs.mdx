SDK ufficiale per Node.js e TypeScript: **`@tratto/email`**

Ogni esempio di questa pagina compila contro la **1.7.0** pubblicata. Dove una
funzionalità richiede una versione precisa, la pagina dichiara la minima che ce
l'ha, mai la più recente: quella invecchia da sola.

## Installazione

```bash
npm install @tratto/email
```

## Inizializzazione

La classe esportata è `Tratto`, e la chiave API è un **argomento posizionale**,
non un oggetto di opzioni:

```typescript
import { Tratto } from '@tratto/email';

const tratto = new Tratto(process.env.TRATTO_API_KEY!);
```

Un secondo argomento facoltativo sovrascrive la base URL:

```typescript
const tratto = new Tratto(process.env.TRATTO_API_KEY!, {
  baseUrl: 'https://api.tratto.email',
});
```

## Invia Email

`emails.send` risolve a `{ id }`, nient'altro. Per leggere lo status, rileggi
l'email.

```typescript
const { id } = await tratto.emails.send({
  from: 'hello@tuodominio.it',
  to: 'user@example.com',
  subject: 'Ciao!',
  text: 'Benvenuto a Tratto',
  html: '<h1>Benvenuto!</h1>',
});

console.log(id); // email_abc123
```

`from` si può omettere dalla **1.5.0 o successiva**: Tratto usa allora il mittente transazionale del workspace, o il mittente generale se manca. Vedi [Mittenti](/it/docs/senders#transazionale).

La chiave di idempotenza è il secondo argomento:

```typescript
await tratto.emails.send(
  { from: 'hello@tuodominio.it', to: 'user@example.com', subject: 'Ciao', text: 'Ciao' },
  'ordine-4711-conferma',
);
```

## Invia con Template

```typescript
const { id } = await tratto.emails.send({
  from: 'hello@tuodominio.it',
  to: 'user@example.com',
  subject: 'Benvenuta, Alice!',
  templateId: 'tmpl_abc123',
  variables: {
    firstName: 'Alice',
    code: 'SECRET123',
  },
});
```

<Callout type="info">
`subject` è obbligatorio su ogni invio, con o senza template. Un template non
ha un oggetto proprio — vedi [Template](/it/docs/templates).
</Callout>

## Invia con Markdown

Invia [Markdown](/it/docs/emailmd-templates) e lascia che il server
renderizzi HTML responsive per email — `markdown` è mutuamente esclusivo con
`html`:

```typescript
const { id } = await tratto.emails.send({
  from: 'hello@tuodominio.it',
  to: 'user@example.com',
  subject: 'Benvenuto!',
  markdown: '# Benvenuto, {{firstName}}!',
  variables: { firstName: 'Alice' },
});
```

Anche `templates.create` e `templates.update` accettano `markdown`, e il tipo
di risposta `Template` espone `format`, `source` e `renderWarnings`.

## Programma un'Email

```typescript
const { id } = await tratto.emails.send({
  from: 'hello@tuodominio.it',
  to: 'user@example.com',
  subject: 'Promemoria',
  text: 'Ci vediamo domani!',
  scheduledAt: new Date('2026-10-01T09:00:00Z'),
});
```

Annullare o riprogrammare un'email programmata si fa via
[HTTP](/it/docs/sdk-http): non esiste ancora un metodo SDK — vedi
[Cosa l'SDK non copre](#cosa-lsdk-non-copre-ancora).

## Invia un Batch

`emails.sendBatch()` invia fino a 100 email in una sola richiesta e richiede la
**1.6.0 o successiva**. Ogni email accetta i campi di `emails.send()` tranne
`scheduledAt`; il secondo argomento, facoltativo, è la
[chiave di idempotenza](/it/docs/idempotency), che vale per tutto il batch.

```typescript
import { randomUUID } from 'node:crypto';

const batch = await tratto.emails.sendBatch(
  [
    { from: 'hello@yourdomain.com', to: 'alice@example.com', subject: 'La tua ricevuta', text: 'Grazie, Alice.' },
    { from: 'hello@yourdomain.com', to: 'bob@example.com', subject: 'La tua ricevuta', text: 'Grazie, Bob.' },
  ],
  randomUUID(),
);

console.log(`${batch.accepted} in coda, ${batch.failed} non inviate`);
for (const e of batch.emails) {
  if (e.status === 'failed') console.error(e.to, e.error.code, e.error.message);
}
```

La chiamata si risolve a ogni 202, **anche quando alcune email non sono
partite**: un'email non partita non ha `id`. Invia di nuovo solo quelle, in un
nuovo batch con una **nuova** chiave. Dopo un 503 o un 500 non è partito
niente: ripeti la stessa chiamata con la **stessa** chiave. Quota, limiti ed
errori sono in [Invio in Batch](/it/docs/send-batch).

## Allegati

Richiede la **`@tratto/email` 1.7.0 o successiva** e un piano a pagamento: il piano Free
risponde `403 PLAN_UPGRADE_REQUIRED`. Prima carica il file, poi indicane l'id
in `emails.send()` o `emails.sendBatch()`.

```typescript
import { readFile } from 'node:fs/promises';

const file = await tratto.attachments.upload(await readFile('fattura.pdf'), {
  filename: 'fattura.pdf',
  contentType: 'application/pdf',
});

await tratto.emails.send({
  from: 'billing@yourdomain.com',
  to: 'alice@example.com',
  subject: 'La tua fattura',
  html: '<p>In allegato.</p>',
  attachments: [{ id: file.id }],
});

const meta = await tratto.attachments.get(file.id); // solo i metadati, mai i byte
await tratto.attachments.delete(file.id);
```

Il contenuto può essere un `Buffer`, un `Uint8Array`, un `ArrayBuffer` o un `Blob`. Limiti, scadenza e spazio sono in [Allegati](/it/docs/attachments).

emails.data.forEach((email) => {

## Aggiungi un Dominio

Il metodo è `add` e prende il dominio come **stringa**:

```typescript
const domain = await tratto.domains.add('hello.tuodominio.it');

// `records` è un array di record DNS, non un oggetto con una chiave per tipo
for (const record of domain.records) {
  console.log(`${record.type} ${record.host} → ${record.value}`);
}
```

## Verifica un Dominio

```typescript
const verified = await tratto.domains.verify('dom_abc123');
console.log(verified.status); // 'pending' | 'verified' | 'failed'
```

## Crea un Contatto

Le proprietà personalizzate stanno in `customFields`. Il campo `metadata` non
esiste:

```typescript
const { id } = await tratto.contacts.create({
  email: 'user@example.com',
  firstName: 'Alice',
  lastName: 'Smith',
  tags: ['vip', 'newsletter'],
  customFields: { plan: 'pro' },
});
```

## Crea una Campagna

`CreateCampaignParams` richiede ancora `templateId`, `audienceId`,
`fromName`, `fromEmail` e `subjectA`. `create` risolve a `{ id }`:

```typescript
const { id } = await tratto.campaigns.create({
  name: 'Saldi Q3',
  templateId: 'tmpl_abc123',
  audienceId: 'aud_abc123',
  fromName: 'Acme',
  fromEmail: 'hello@tuodominio.it',
  subjectA: 'I saldi estivi iniziano oggi',
  subjectB: 'Saldi estivi: 30% di sconto, solo oggi', // oggetto A/B, facoltativo
});

const campaign = await tratto.campaigns.get(id);
console.log(campaign.status); // 'draft'
```

<Callout type="info">
L'API è più permissiva dei tipi della 1.7.0: accetta `html` inline al posto di
un `templateId`, e interpreta un `audienceId` omesso come «tutti i contatti del
workspace». Nessuna delle due cose è esprimibile con l'SDK: per quelle usa
[HTTP](/it/docs/sdk-http).
</Callout>

## Invia una Campagna

```typescript
const sent = await tratto.campaigns.send('camp_xyz789');
console.log(sent.status); // 'sending'
```

Per programmarla, passa una data:

```typescript
await tratto.campaigns.send('camp_xyz789', {
  scheduledAt: new Date('2026-10-01T09:00:00Z'),
});
```

## Ferma una Campagna

`pause` trattiene una campagna che sta spedendo o che è in attesa.
`unschedule` annulla un invio programmato e riporta la campagna a `draft`, e
richiede la **1.2.0 o successiva**:

```typescript
await tratto.campaigns.pause('camp_xyz789');
await tratto.campaigns.unschedule('camp_xyz789');
```

`unschedule` vale solo mentre lo status è `scheduled` e non è uscito niente. Su
una campagna che sta spedendo, già in pausa, o che aspetta la sua
[ondata di prova](/it/docs/campaigns#ondata-di-prova) risponde `409 CONFLICT`,
perché una parte della lista può già avere l'email. Mettila in pausa invece.

`Campaign.pausedReason` dice perché una campagna si è fermata da sola, e
richiede a sua volta la **1.2.0 o successiva**. Vale `'quota_exceeded' |
'schedule_missed' | 'bounce_rate' | null`, e `'bounce_rate'` è lo
[stop automatico sui rimbalzi](/it/docs/campaigns#tasso-di-rimbalzi):

```typescript
const campaign = await tratto.campaigns.get('camp_xyz789');
if (campaign.pausedReason === 'bounce_rate') {
  // Pulisci la lista prima di richiamare send.
}
```

## Statistiche di una Campagna

Il metodo è `getStats`. **I tassi sono percentuali**: `50` significa 50%, non
`0.5` — la stessa scala di [Analytics](/it/docs/analytics).

```typescript
const stats = await tratto.campaigns.getStats('camp_xyz789');

console.log(stats.stats.delivered);   // 4950
console.log(stats.rates.openRate);    // 50 → 50%
console.log(stats.rates.deliveryRate) // 99 → 99%
```

<Callout type="warn">
Un alert scritto come `rates.deliveryRate < 0.95` non scatterà mai. Il
confronto giusto è `< 95`.
</Callout>

## Analytics

`AnalyticsPeriod` è `'7d' | '30d' | '90d' | '180d' | '1y'` (gli ultimi due
richiedono la **1.1.1 o successiva**):

```typescript
const summary = await tratto.analytics.getSummary('30d');
console.log(summary.delivered);
```

`180d` e `1y` leggono l'aggregato di lungo periodo, che contiene solo dati live:
l'API li rifiuta per una chiave in modalità test.

## Gestione degli Errori

`TrattoError` espone `code`, `statusCode`, `docs` e `details`:

```typescript
import { Tratto, TrattoError } from '@tratto/email';

const tratto = new Tratto(process.env.TRATTO_API_KEY!);

try {
  await tratto.emails.send({
    from: 'hello@nonverificato.it', // non verificato
    to: 'user@example.com',
    subject: 'Ciao',
    text: 'Test',
  });
} catch (error) {
  if (error instanceof TrattoError) {
    // Il messaggio nomina il dominio non verificato.
    console.error(error.code, error.statusCode, error.message);
  }
}
```

Vedi [Codici di Errore](/it/docs/error-codes) per l'elenco completo.

Su un 422 `VALIDATION_ERROR`, `details` indica quale campo è sbagliato, per
esempio `[{ path: '/emails/3/to', message: '...' }]` per la quarta email di un
batch. Richiede la **1.6.0 o successiva** e vale `undefined` quando l'API non
lo invia.

## Cosa l'SDK non copre ancora

Questi endpoint esistono nell'API e **non hanno un metodo SDK** nella 1.7.0.
Chiamali via [HTTP](/it/docs/sdk-http) finché l'SDK non li recupera:

| Funzionalità | HTTP |
|---|---|
| Annullare un'email programmata | `DELETE /v1/emails/{id}` |
| Riprogrammare un'email | `PATCH /v1/emails/{id}` |
| Leggere un singolo contatto | `GET /v1/contacts/{id}` |
| Modificare / eliminare una campagna | `PATCH`, `DELETE /v1/campaigns/{id}` |
| Click sui link di una campagna | `GET /v1/campaigns/{id}/links` |
| Modificare / eliminare / ricalcolare un'audience | `PATCH`, `DELETE`, `POST …/refresh` su `/v1/audiences/{id}` |
| Elencare o rimuovere i contatti di un'audience | `GET`, `DELETE` su `/v1/audiences/{id}/contacts` |
| Anteprima di rendering del markdown | `POST /v1/templates/render-preview` |
| Gestione delle chiavi API | `/v1/api-keys` |
| Logo del marchio di workspace | `PUT`, `DELETE /v1/workspace/brand/logo` |

Mancano dai tipi della 1.7.0 anche alcuni campi di risposta più recenti:
`Workspace` non ha `limits` né `brand`, `Contact` non ha `trackingOptOut`,
e `CampaignStats` non ha `skipped`,
`untracked` né `variants`. L'API li restituisce; i tipi non li descrivono
ancora. `TrattoError` espone `docs` ma non `suggestion`, che invece l'SDK
Python ha.

Verificato sulla `@tratto/email` 1.7.0 pubblicata, il 2026-10-27: le dieci righe
sono ancora scoperte, e `ListContactsParams.q` è coperto dalla 1.4.0
(`contacts.list({ q })`). Ogni riga di questa tabella è la
promessa che la lacuna c'è ancora: va riletta a ogni rilascio dell'SDK.
