The official SDK for Node.js and TypeScript: **`@tratto/email`**

Every example on this page typechecks against the version named next to it, and otherwise against **1.2.0**. Where a feature needs
a particular version, the page names the minimum one that has it; it never
names the newest, because that goes stale on its own.

## Installation

```bash
npm install @tratto/email
```

## Initialization

The exported class is `Tratto`, and the API key is a **positional argument**,
not an options object:

```typescript
import { Tratto } from '@tratto/email';

const tratto = new Tratto(process.env.TRATTO_API_KEY!);
```

An optional second argument overrides the base URL:

```typescript
const tratto = new Tratto(process.env.TRATTO_API_KEY!, {
  baseUrl: 'https://api.tratto.email',
});
```

## Send Email

`emails.send` resolves to `{ id }` — nothing else. To read the status, fetch
the email back.

```typescript
const { id } = await tratto.emails.send({
  from: 'hello@yourdomain.com',
  to: 'user@example.com',
  subject: 'Hello!',
  text: 'Welcome to Tratto',
  html: '<h1>Welcome!</h1>',
});

console.log(id); // email_abc123
```

`from` can be omitted from **1.5.0 or newer**: Tratto then uses the workspace transactional sender, or the general default sender if there is none. See [Senders](/en/docs/senders#transactional).

Pass an idempotency key as the second argument:

```typescript
await tratto.emails.send(
  { from: 'hello@yourdomain.com', to: 'user@example.com', subject: 'Hi', text: 'Hi' },
  'order-4711-confirmation',
);
```

## Send with Template

```typescript
const { id } = await tratto.emails.send({
  from: 'hello@yourdomain.com',
  to: 'user@example.com',
  subject: 'Welcome, Alice!',
  templateId: 'tmpl_abc123',
  variables: {
    firstName: 'Alice',
    code: 'SECRET123',
  },
});
```

<Callout type="info">
`subject` is required on every send, template or not. A template carries no
subject of its own — see [Templates](/en/docs/templates).
</Callout>

## Send with Markdown

Send [Markdown](/en/docs/emailmd-templates) and let the server render
responsive email HTML — `markdown` is mutually exclusive with `html`:

```typescript
const { id } = await tratto.emails.send({
  from: 'hello@yourdomain.com',
  to: 'user@example.com',
  subject: 'Welcome!',
  markdown: '# Welcome, {{firstName}}!',
  variables: { firstName: 'Alice' },
});
```

`templates.create` and `templates.update` take `markdown` too, and the
`Template` response type carries `format`, `source` and `renderWarnings`.

## Schedule Email

```typescript
const { id } = await tratto.emails.send({
  from: 'hello@yourdomain.com',
  to: 'user@example.com',
  subject: 'Reminder',
  text: 'See you tomorrow!',
  scheduledAt: new Date('2026-10-01T09:00:00Z'),
});
```

Canceling or rescheduling a scheduled email is available over
[HTTP](/en/docs/sdk-http) but has no SDK method yet — see
[What the SDK does not cover](#what-the-sdk-does-not-cover-yet).

## Send a Batch

`emails.sendBatch()` sends up to 100 emails in one request and requires
**1.6.0 or newer**. Each email takes the fields of `emails.send()` except
`scheduledAt`; the optional second argument is the
[idempotency key](/en/docs/idempotency), which covers the whole batch.

```typescript
import { randomUUID } from 'node:crypto';

const batch = await tratto.emails.sendBatch(
  [
    { from: 'hello@yourdomain.com', to: 'alice@example.com', subject: 'Your receipt', text: 'Thanks, Alice.' },
    { from: 'hello@yourdomain.com', to: 'bob@example.com', subject: 'Your receipt', text: 'Thanks, Bob.' },
  ],
  randomUUID(),
);

console.log(`${batch.accepted} queued, ${batch.failed} failed`);
for (const e of batch.emails) {
  if (e.status === 'failed') console.error(e.to, e.error.code, e.error.message);
}
```

The call resolves on every 202, **also when some emails failed**: a failed
email has no `id`. Send only those again, in a new batch with a **new** key.
After a 503 or a 500 nothing was sent: repeat the same call with the **same**
key. Quota, limits and errors are in [Send a Batch](/en/docs/send-batch).

## Get Email Status

```typescript
const email = await tratto.emails.get('email_abc123');
console.log(email.status); // 'delivered'
console.log(email.events); // full timeline
```

## List Emails

```typescript
const emails = await tratto.emails.list({
  limit: 50,
  after: 'cursor_value', // for pagination
});

emails.data.forEach((email) => {
  console.log(`${email.id}: ${email.status}`);
});
```

## Add a Domain

The method is `add`, and it takes the domain as a **string**:

```typescript
const domain = await tratto.domains.add('hello.yourdomain.com');

// `records` is an array of DNS records, not an object keyed by type
for (const record of domain.records) {
  console.log(`${record.type} ${record.host} → ${record.value}`);
}
```

## Verify Domain

```typescript
const verified = await tratto.domains.verify('dom_abc123');
console.log(verified.status); // 'pending' | 'verified' | 'failed'
```

## Create Contact

Custom properties live in `customFields`. There is no `metadata` field:

```typescript
const { id } = await tratto.contacts.create({
  email: 'user@example.com',
  firstName: 'Alice',
  lastName: 'Smith',
  tags: ['vip', 'newsletter'],
  customFields: { plan: 'pro' },
});
```

## Create Campaign

`CreateCampaignParams` still requires `templateId`, `audienceId`,
`fromName`, `fromEmail` and `subjectA`. `create` resolves to `{ id }`:

```typescript
const { id } = await tratto.campaigns.create({
  name: 'Q3 Sale',
  templateId: 'tmpl_abc123',
  audienceId: 'aud_abc123',
  fromName: 'Acme',
  fromEmail: 'hello@yourdomain.com',
  subjectA: 'Our summer sale starts today',
  subjectB: 'Summer sale: 30% off, today only', // optional A/B subject
});

const campaign = await tratto.campaigns.get(id);
console.log(campaign.status); // 'draft'
```

<Callout type="info">
The API itself is more permissive than the 1.6.0 types: it accepts inline
`html` instead of a `templateId`, and treats an omitted `audienceId` as "every
contact in the workspace". Neither is expressible through the SDK yet. Use
[HTTP](/en/docs/sdk-http) for those.
</Callout>

## Send Campaign

```typescript
const sent = await tratto.campaigns.send('camp_xyz789');
console.log(sent.status); // 'sending'
```

Schedule it instead by passing a date:

```typescript
await tratto.campaigns.send('camp_xyz789', {
  scheduledAt: new Date('2026-10-01T09:00:00Z'),
});
```

## Stop a Campaign

`pause` holds a campaign that is sending or waiting. `unschedule` cancels a
scheduled send and puts the campaign back to `draft`; it needs **1.2.0 or
newer**:

```typescript
await tratto.campaigns.pause('camp_xyz789');
await tratto.campaigns.unschedule('camp_xyz789');
```

`unschedule` only applies while the status is `scheduled` and nothing has left.
On a campaign that is sending, already paused, or waiting out its
[probe wave](/en/docs/campaigns#probe-wave) it answers `409 CONFLICT`, because
part of the list may already have the email. Pause it instead.

`Campaign.pausedReason` says why a campaign stopped on its own, and also needs
**1.2.0 or newer**. It reads `'quota_exceeded' | 'schedule_missed' |
'bounce_rate' | null`, and `'bounce_rate'` is the
[automatic bounce stop](/en/docs/campaigns#bounce-rate):

```typescript
const campaign = await tratto.campaigns.get('camp_xyz789');
if (campaign.pausedReason === 'bounce_rate') {
  // Clean the list before calling send again.
}
```

## Get Campaign Stats

The method is `getStats`. **Rates are percentages**: `50` means 50%, not
`0.5` — the same scale as [Analytics](/en/docs/analytics).

```typescript
const stats = await tratto.campaigns.getStats('camp_xyz789');

console.log(stats.stats.delivered);   // 4950
console.log(stats.rates.openRate);    // 50 → 50%
console.log(stats.rates.deliveryRate) // 99 → 99%
```

<Callout type="warn">
An alert written as `rates.deliveryRate < 0.95` will never fire. The
comparison you want is `< 95`.
</Callout>

## Analytics

`AnalyticsPeriod` is `'7d' | '30d' | '90d' | '180d' | '1y'` (the last two since
1.1.1):

```typescript
const summary = await tratto.analytics.getSummary('30d');
console.log(summary.delivered);
```

`180d` and `1y` read the long-term aggregate, which only holds live data: the
API rejects them for a test-mode key.

## Error Handling

`TrattoError` carries `code`, `statusCode`, `docs` and `details`:

```typescript
import { Tratto, TrattoError } from '@tratto/email';

const tratto = new Tratto(process.env.TRATTO_API_KEY!);

try {
  await tratto.emails.send({
    from: 'hello@unverified.com', // not verified
    to: 'user@example.com',
    subject: 'Hello',
    text: 'Test',
  });
} catch (error) {
  if (error instanceof TrattoError) {
    // The message names the domain that is not verified.
    console.error(error.code, error.statusCode, error.message);
  }
}
```

See [Error Codes](/en/docs/error-codes) for the full list.

On a 422 `VALIDATION_ERROR`, `details` says which field is wrong, for example
`[{ path: '/emails/3/to', message: '...' }]` for the fourth email of a batch.
It requires **1.6.0 or newer** and is `undefined` when the API sends none.

## What the SDK does not cover yet

These endpoints exist in the API and have **no SDK method** in 1.6.0. Call
them over [HTTP](/en/docs/sdk-http) until the SDK catches up:

| Capability | HTTP |
|---|---|
| Cancel a scheduled email | `DELETE /v1/emails/{id}` |
| Reschedule an email | `PATCH /v1/emails/{id}` |
| Get one contact | `GET /v1/contacts/{id}` |
| Update / delete a campaign | `PATCH`, `DELETE /v1/campaigns/{id}` |
| Campaign link clicks | `GET /v1/campaigns/{id}/links` |
| Update / delete / refresh an audience | `PATCH`, `DELETE`, `POST …/refresh` on `/v1/audiences/{id}` |
| List or remove audience contacts | `GET`, `DELETE` on `/v1/audiences/{id}/contacts` |
| Render a markdown preview | `POST /v1/templates/render-preview` |
| API key management | `/v1/api-keys` |
| Workspace brand logo | `PUT`, `DELETE /v1/workspace/brand/logo` |

Some newer response fields are likewise absent from the 1.6.0 types:
`Workspace` has no `limits` or `brand`, `Contact` has no `trackingOptOut`,
and `CampaignStats` has no `skipped`,
`untracked` or `variants`. The API returns them; the types do not describe
them yet. `TrattoError` carries `docs` but not `suggestion`, which the Python
SDK does expose.

Checked against the published `@tratto/email` 1.6.0 on 2026-10-21: the ten rows
are still uncovered, and `ListContactsParams.q` is covered from 1.4.0
(`contacts.list({ q })`). A row here is a promise that the gap
is still real, so it is worth rereading at every SDK release.
